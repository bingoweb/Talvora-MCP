## General rules for every card

- AGENTS.md applies in full (Context7 gate, modern-by-default, delivery gates, desktop progress contract, `talvora_apply_patch` as primary editor).
- **Test first** (red), then code. Prefer **behavioural** tests. Do **not** add new regex-over-source assertions unless the card prescribes one; when you touch a file covered by a `*SourceRegression.ps1`, replace the affected assertions with behaviour where feasible, otherwise update them in the same commit and say so in the Log.
- **Definition of done** (every card):
  1. `dotnet restore Talvora.slnx --locked-mode` and the installer project restore pass **without** env overrides.
  2. `dotnet build Talvora.slnx -c Release` → 0 warnings, 0 errors (`TreatWarningsAsErrors`).
  3. Targeted tests for the card + the always-on set (`scripts/Invoke-QualityGate.ps1`, last line `Hepsi geçti.`).
  4. Runtime/packaging/shared-infrastructure cards: canonical installer (`scripts/Deploy-Windows-Installer.ps1`) + exact-installed smoke; record the installed `sourceCommit` from `/healthz`.
  5. `.context7/verification.json` as AGENTS.md → CONTEXT7 PROTOCOL says; when it changes, it holds this change only. There is no Awwwards evidence.
  6. `docs/codex/STATUS.md` updated (queue tick + one Log entry, English), one commit with trailer `Card: <ID>`; mirror the evidence to the active Gitea issue.
- User-facing strings: ordinary Turkish, no tool names / exit codes / stack traces / transport terms. Errors say what went wrong, what is protected, what happens next. Example: `"Bu istek Talvora'ya yerel bir uygulamadan gelmediği için reddedildi. Sistem güvende; bağlantınızı Talvora ayarlarından yeniden yapın."`
- Tool **descriptions** stay English (model-facing). Tool **titles** (human-facing in client approval dialogs) are short Turkish.
- Never print, copy or commit secrets. Never read files in `C:\ProgramData\Talvora\Secrets` content; listing names and ACLs is enough.
- **Security stays proportionate** (user, 2026-11-14): Talvora is a local MCP its owner runs on their own computer by their own choice. A card adds a security or privacy guard only against a concrete, likely accident and never where it makes an ordinary tool task harder; no extra refusals, confirmations or restrictions "just in case". A guard that breaks a normal task is a bug. The agent never adds a guard a card does not name.
- Push as STATUS → Fixed facts → "Push" says.

### D137 — background user jobs run through `talvora-user-runner relay`

**Why:** see D135. `talvora_job_start` with `runAs` `user` (the default) still starts `pwsh` with `UserJobRelay.RunnerScript` (`JobTools.Lifecycle.cs`), which loads `Talvora.Shared.dll`; under .NET 11 that breaks at run time and no gate check catches it (the smoke calls `UserJobRelay.Run` in-process). Needs D135 (the runner) and D136 (`UserRunnerLocator`).

**Read:** D135, D136; `src/Talvora.Shared/UserJobRelay.cs` (all); `src/Talvora/Tools/JobTools.Lifecycle.cs` near 121–169 and `CreateJobPipe` near 241–256; `tests/Talvora.Smoke/SmokeScenarios.SharedInfrastructure.cs`, the relay block near 203–283; `src/Talvora.Shared/ProcessRunner.cs` (`RunAsync`, near 28).

**Files:** `src/Talvora.UserRunner/src/main.rs` and a new `src/Talvora.UserRunner/src/relay.rs`, `src/Talvora.UserRunner/tests/relay.rs` (new), `src/Talvora.Shared/UserJobRelay.cs`, `src/Talvora/Tools/JobTools.Lifecycle.cs`, `tests/Talvora.Smoke/SmokeScenarios.SharedInfrastructure.cs` (the relay block only), `docs/codex/STATUS.md`, `.context7/verification.json`.

**Context7:** gerekmiyor (a named pipe client is opened as a file: `OpenOptions` on `\\.\pipe\<name>` with `read(true)` or `write(true)` asks for the same `GENERIC_READ`/`GENERIC_WRITE` access the .NET client asked for, which `CreateJobPipe`'s ACL grants the user; the servers stay .NET `NamedPipeServerStream`).

**Decisions:**
1. `talvora-user-runner.exe relay --request <path>`; the usage line becomes `usage: talvora-user-runner run|relay --request <path>`. The request is today's `UserJobRequest` with the same PascalCase names (`Executable`, `WorkingDirectory`, `Arguments`, `Environment`, `ClearEnvironment`, `StandardInputPipe`, `StandardOutputPipe`, `StandardErrorPipe`, `ChildProcessIdPath`, `ExitCodePath`), `#[serde(deny_unknown_fields)]`; read it, delete the file, then parse.
2. Factor D135's start into one function both modes call: environment (for `relay`, `env_clear()` first when `ClearEnvironment`), then the program or batch building, `current_dir`, `CREATE_NO_WINDOW`. `relay` writes no `result.json` and reads no stdin file.
3. Pipes: open `\\.\pipe\<StandardInputPipe>` for reading, the output and error pipes for writing, each retried every 100 ms while it is not found or busy, at most 15 s each. A pipe that does not open → stderr `pipe not available: <name>`, `1` written to `ExitCodePath`, exit 1.
4. Start the child with piped stdin, stdout and stderr; write its PID as text to `ChildProcessIdPath`. Forward with `std::thread::spawn`: stdin pipe → child stdin; child stdout → output pipe; child stderr → error pipe; a forwarder whose pipe write fails keeps reading the child to the end. After the child exits, wait for the **stdout and stderr** forwarders only, 5 s in total (`mpsc::channel` + `recv_timeout`, as D135 Decision 7); never wait for the stdin forwarder (the service keeps that pipe open). Write the exit code as text to `ExitCodePath` and leave with `std::process::exit(<child exit code>)` (the service reads the runner's own exit code).
5. A start failure writes its message to the error pipe, `1` to `ExitCodePath`, and exits 1.
6. `JobTools.Lifecycle.cs` starts `UserRunnerLocator.Resolve()` with `relay --request <request path>`; `jobrunner.ps1`, `scriptPath`, the `-HelperAssemblyPath` argument, the pwsh resolution and its "PowerShell 7 is required" `FileNotFoundException` go; pipes, ACLs, the 30 s connect, the readers and stop handling stay.
7. `UserJobRelay.cs` keeps only `UserJobRequest`; `RunnerScript`, `Run` and their helpers go, with the usings they leave unused.
8. The smoke block starts the runner with `ProcessRunner.RunAsync(UserRunnerLocator.Resolve(), <root>, ["relay", "--request", requestPath], timeoutSeconds: 60)` in place of `Task.Run(() => UserJobRelay.Run(requestPath))`, takes the exit code from its result, and keeps every assertion (exit 3, `got:ping`, `relay-err`, the exit file, PID > 0, the `ARG1`–`ARG8` batch set). It finds the runner because `ProcessRunnerRegression.ps1` sets `TALVORA_USER_RUNNER_PATH` (D136).

**Tests:** the smoke block is the relay's test (it serves the pipes). `relay.rs`: `relay_bad_request_exits_1` (an unknown field → exit 1, stderr not empty, done within 5 s, no `ExitCodePath` file written).

**Don't:** change the job tool contracts, pipe names, ACLs or `JobTools.Persistence.cs`/`JobTools.StopDelete.cs`; keep pwsh in this path.
